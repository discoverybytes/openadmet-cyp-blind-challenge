# OpenADMET CYP3A4 Structure Track — discoverybytes

**Challenge:** OpenADMET CYP Blind Challenge — Structure Prediction Track  
**Target:** Human Cytochrome P450 3A4 (CYP3A4 / UniProt P08684), with its haem cofactor  
**Task:** Predict protein–ligand complexes for 20 drug-like ligands from SMILES alone  
**Metrics:** three, all measured against the blinded cryo-EM structures  

- **LDDT-PLI** — do the predicted protein–ligand contacts match the real ones? 0 to 1, higher
  is better. This is the headline score.
- **BiSyRMSD** — after lining up the pocket, how far is the ligand from where it should be,
  in Å? Lower is better.
- **LDDT-LP** — is the pocket itself the right shape? 0 to 1, higher is better.

---

## Summary

The ligand and the protein were predicted together in one pass — co-folding, with Boltz-2 —
from the ligand's SMILES and the CYP3A4 sequence. One CYP3A4 crystal structure was given as
a template, the haem was supplied complete as a standard 43-atom group, and a weak restraint
kept the ligand near the haem iron. Each compound was predicted 25 times, and one rule chose
one of the 25: the centre of the biggest cluster of poses. The predicted coordinates were
submitted untouched.

Final submission: **LDDT-PLI 0.4548**, BiSyRMSD 3.434, LDDT-LP 0.8167.

Data analysis, gating, YAML generation and the experimental design for this project were
performed by Claude (Anthropic), operating in Claude Code. The human operator
(discoverybytes) defined the goals, ran the co-folding, chose templates,
reviewed results, made several decisive interventions on method, and made all submission
decisions. This report was also generated by Claude.

## Approach

### Template and cofactor

One template for all 20 compounds: **9BVB**, protein-only, chain A.

The choice was made on public evidence about the references. The UCSF group running the
challenge deposited five CYP3A4 cryo-EM structures five days after the track opened — not the
blinded references, but the same group and method, and probably the same construct and
conditions. Ranking 122 deposited CYP3A4 entries by how closely their pocket backbone matches
all five put **9BVB first** (1.01 Å average, 1.24 Å at worst).

The haem is supplied as `ccd: HEM`, which takes it from the standard component dictionary —
all 43 atoms including the iron, named `FE`.

### Pocket constraint

A weak restraint keeps the ligand within 6 Å of the haem iron. `force: false` makes it a nudge
rather than a hard requirement:

```yaml
constraints:
  - pocket:
      binder: C
      contacts: [[B, FE]]
      max_distance: 6
      force: false
```

Tightening it to 3 Å and making it a hard requirement changed nothing (0.4092 against 0.4165).

### Sequence alignment

`--use_msa_server` gives the model a multiple sequence alignment — thousands of related P450
sequences — instead of the CYP3A4 sequence on its own. This was the **largest gain from any
single change in the project, +0.0200 LDDT-PLI** (0.4165 → 0.4365).

It also made the model visibly more certain. The 25 poses per compound came out closer
together (4.85 Å apart typically, down to 3.97 Å), and the most central pose sat nearer the
rest (1.76 Å down to 1.24 Å). The alignment holds 14,302 sequences, 14,091 of them distinct.

### Sampling and selection

Five random seeds × five predictions each = 25 poses per compound, with 3 internal refinement
passes (recycling steps) and `--use_potentials` on.

The 25 poses were clustered, and the submitted pose is the **centre of the biggest cluster**
(called "plurality" below). The same rule was applied to all 20 compounds, with ties going to
the tighter cluster.

### Stereochemistry

Three compounds have an undefined stereocentre (`2312554`, `2395415`, `2312966`). Each was
enumerated as an `_R`/`_S` pair and co-folded separately — 23 entries rather than 20 — with
one configuration chosen per compound ID at submission time. The submitted set uses **R**
throughout.

## Final Submission

`20261014_boltz_9bvb-msa_plurality.zip`
SHA-256 `cc1adc45f513681c8c546967123c12de23a044d93dd21fb8346cc2b7b6606734`

20 × `{Molecule_Name}.pdb`, three chains each (protein, HEM, LIG), ligand residue `LIG`,
unmodified Boltz-2 output. Validator PASS, PoseBusters 20/20 PASS with zero failing checks.

**The caveat, stated because it matters more than the number.** 0.4548 is a real score against
the real ground truth, but it is not what this method would score again. Taking a 50-pose pool
and working through all 252 ways of drawing five seeds from ten, the submitted set of 20 poses
comes back in only **4 of those 252 draws (1.6%)**: for `2313300` and `2395342` it holds
clusters that win only 7% and 13% of the time. A fresh run of the same method lands near
**0.415–0.43**, which is what the 50-pose pool scored (0.4151).

## Additional Results

Each of the following was tested either on the leaderboard directly, or against a comparison
in which the only difference was which poses were picked. None improved the score.

**Tidying up the predicted poses**
- YASARA relaxation of all 25 poses per compound: 0.4195 — no real change
- RDKit MMFF94 and YASARA strain relaxation, against the identical unrelaxed poses: **no
  change** (0.4476 against 0.4482), ligands moving only 0.2–0.3 Å

**How many poses**
- 25 poses per compound → 50, same selection rule: **0.4151**, slightly worse
- Internal refinement passes 3 → 6: lost in the seed-to-seed scatter, and 3 is the most the
  model was trained with
- Thinning the alignment to 256 sequences (`--subsample_msa`): **0.3876**

**What the model was told**
- Restraint tightened from 6 Å nudge to 3 Å hard requirement: 0.4092
- A different template per compound, matched on ligand similarity: 0.4047

**Picking one pose out of the 25**
- most central pose 0.4365 · best-agreeing contacts 0.4207 · tightest-packed member of the
  biggest cluster 0.4482 · **biggest-cluster centre 0.4548**
- The model's own confidence scores, contact fingerprints and ligand strain were all tried as
  the deciding criterion, and none beat picking the biggest cluster's centre

## Reproduction

### Requirements

```
python 3.12          # analysis, gating
rdkit, numpy, pandas, MDAnalysis, posebusters, gemmi, plotly, pytest
boltz == 2.2.1       # co-folding, in a separate Python 3.12 env with CUDA
```

Hardware: one RTX 3080 Ti (12 GB), 24 threads. A five-seed run over 23 entries takes
roughly 7–9 h.

### Inputs

One YAML per entry (23 entries: 20 compounds, 3 of them stereo-enumerated):

```yaml
version: 1
sequences:
  - protein:
      id: A
      sequence: MALIPDLAMETWLLLAVSLVLLYLYGTHSHGLFKKLGIPGPTPLPFLGNILSYHKG...   # P08684, 503 aa
  - ligand:
      id: B
      ccd: HEM
  - ligand:
      id: C
      smiles: 'CCc1[nH]ccc1C(=O)Nc1ccc(-n2ccnc2)cc1'
constraints:
  - pocket:
      binder: C
      contacts: [[B, FE]]
      max_distance: 6
      force: false
templates:
  - cif: 9BVB_protein.cif
    chain_id: A
    template_id: A
```

Generated by:

```bash
python scripts/make_cofold_yamls.py --name 20261013_boltz2_9bvb-msa \
    --pocket-heme --template cofold/templates/9BVB_protein.cif --template-chain A \
    --bundle-template --smiles-csv docking_inputs/stereo_expanded.csv --msa server
```

The YAMLs carry **no `msa:` key**, which is what lets `--use_msa_server` take effect. Writing
`msa: empty` instead pins the run to the bare sequence and the flag is silently ignored — a
failure mode that produces a clean-looking null result for an experiment that never ran.

### Co-folding

Run once per seed, from the set directory (the template path is relative and Boltz resolves
it against the working directory):

```bash
conda activate boltz2
cd cofold/20261013_boltz2_9bvb-msa
for SEED in 42 21 99 300 550; do
  boltz predict yaml \
    --out_dir "out_20261013_msa_seed$SEED" \
    --model boltz2 \
    --seed "$SEED" \
    --diffusion_samples 5 \
    --recycling_steps 3 \
    --output_format pdb \
    --use_msa_server \
    --use_potentials
done
```

### Staging and selection

Boltz's PDB writer labels every HETATM residue `LIG`, so the haem and the ligand arrive under
the same name; the ingest step repairs this from the chains declared in the YAML, and refuses
any file whose chain B does not carry 43 atoms including an iron.

```bash
for SEED in 42 21 99 300 550; do
  python scripts/ingest_boltz_poses.py \
      "cofold/20261013_boltz2_9bvb-msa/out_20261013_msa_seed$SEED/boltz_results_yaml/predictions" \
      --out runs/20261014_boltz_9bvb-msa --tag "s$SEED"
done

python scripts/plurality_selection.py runs/20261014_boltz_9bvb-msa
```

### Building the submission

`plurality_selection.py` prints the `--pick` arguments directly:

```bash
python scripts/build_submission.py runs/20261014_boltz_9bvb-msa --label plurality \
  --pick OCNT-2395436=S42M3  --pick OCNT-2395503=S300M0 --pick OCNT-2395342=S21M0 \
  --pick OCNT-2395712=S99M1  --pick OCNT-2313429=S42M1  --pick OCNT-2395464=S99M1 \
  --pick OCNT-2313397=S42M4  --pick OCNT-2395415=R_S21M1 --pick OCNT-2395645=S300M1 \
  --pick OCNT-2395789=S550M4 --pick OCNT-2312554=R_S42M1 --pick OCNT-2395457=S21M2 \
  --pick OCNT-2313038=S300M1 --pick OCNT-2313300=S550M4 --pick OCNT-2395460=S300M3 \
  --pick OCNT-2315379=S42M1  --pick OCNT-2535422=S550M1 --pick OCNT-2535519=S42M2 \
  --pick OCNT-2395328=S550M1 --pick OCNT-2312966=R_S550M1
```

This normalises the PDBs, writes the zip, and checks it: the official
`structure_validation.py` with the expected IDs and SMILES, then PoseBusters in `dock`
configuration with protein **and** haem as context, which is how the scorer calls it. A zip is
"ready" only when both pass with zero failures. The check report and SHA-256 are written
alongside the archive.

### Where the numbers come from

Every score quoted here is a row of `leaderboard/leaderboard_log.csv`, tied to one archive's
SHA-256 and one run manifest. The score-progression table is regenerated by
`scripts/rank_submissions.py`; the measurements behind each claim are regenerated by the named
scripts recorded in `docs/findings/`.
